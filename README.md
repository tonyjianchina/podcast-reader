# Podcast Reader

把一集播客变成一篇**可精读、可标注、可查词的文章**的私人阅读器。

不是英语学习 App,也不是播客客户端 —— 详见 [DESIGN.md](DESIGN.md)。
英语提升是「读自己真正想看的资讯」的副产品。

## 用法

```bash
# 启动后端 + 阅读界面,浏览器打开 http://127.0.0.1:8787
uv run et serve

# 或者不开服务,直接在终端导入并处理一集
uv run et import "https://podcasts.apple.com/us/podcast/xxx/id123456"
uv run et import "https://www.xiaoyuzhoufm.com/episode/xxxxx"
uv run et import "https://www.youtube.com/watch?v=xxxxx"

# 看看有哪些内容
uv run et list

# 给视频站导入的单集补标题/封面/上传日期(不带 id: 补所有「未命名单集」或缺封面的)
# 只改元数据列, 不碰状态、音频、句子、段落; 可以在服务运行时执行
uv run et refresh-meta [episode_id ...]

# 单独试一张释义卡
uv run et define ubiquitous "Smartphones have become ubiquitous in modern life."

# 用分块方案重转录一集(校准时间轴,会重建段落与逐句中译)
uv run et retranscribe <episode_id>
```

在网页里:

- **底部常驻播放器**:打开可读单集后立即出现,集中展示封面、标题、进度、回退/前进 10 秒、
  播放/暂停、语速和音量;**返回列表、打开别的集,声音都不会断**
- **播放速度**:默认 1×,点击倍速按钮直接选择 0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 六档,
  手机和电脑共用同一设置
- **学习控制**:定位当前句、自动连播和显示中译与播放器相连;电脑端是可收起的第二行,
  手机端是底部导航上方的迷你播放器,点「学习」后原位展开为底部面板
- **阅读设置**:字号(16~24)、行距(1.55~2.1)和深浅外观收纳在顶部齿轮设置页,
  带实时阅读预览,不占用阅读区的高频操作位置
- **点句子** → 从这句开始播,当前句会高亮;不勾连播时**播完这句就停**,等你查词
- **点单词** → 弹释义卡。只有**长度 ≥4 的词**(或已标过的词)才算"值得查";
  点到 the / of / and 这类虚词会直接当作"点句子"去播放 —— 手机上误触大多落在这些短词上。
  (中译层设了 `pointer-events:none`:它是块级元素、盖在单词上, 否则点单词中部会打不中)
- **点单词** → 弹出释义卡(语境义 / 音标 / 词根 / 其他义 / 关联词句)
- 释义卡里可以**标记为生词**,标记过的词在**所有单集**的正文里永久高亮(按同一词形小写匹配,不做词形还原)
- **生词本**(导航中的「生词本」按钮,或地址 `#vocab`):**所有标记过的词集中在一页**,
  按单集分组,组内同一个词只出一条(标过两次会标 `×2`)。每条显示词 + 中文语境义 +
  那句原句(原句里的那个词会高亮),三个动作:
  - **点词条** → 弹出释义卡(走 `/vocab/{词}/explain`,按当时那句原句命中缓存,**不重复花钱**)
  - **跳到原文这一句 →** → 打开那一集,自动滚到并标出当初标这个词的那一句
  - **更多 → 移出生词本** → 从生词本移除(会先确认一次)
- 快捷键:**空格** 重听当前句,`[` / `]` 上一句 / 下一句

## 导入来源支持情况

| 来源 | 状态 |
|---|---|
| 任意 RSS 地址 | ✅ 导入 feed 里最新一集 |
| Apple Podcasts 节目链接(`.../id123456`) | ✅ 走 iTunes Lookup API,导入最新一集 |
| Apple Podcasts 单集链接(`...?i=<trackId>`) | ✅ 用 Lookup 找到该集的 guid,在 feed 里精确选中这一集(依次比 guid、音频地址、标题+日期);feed 里没有就用 Lookup 给的音频地址;都找不到直接报错,不会退化成最新一集 |
| YouTube / Bilibili 链接 | ✅ 交给 yt-dlp;导入时先读元数据,带上真实标题、封面(高清 https 缩略图)、上传日期、时长,同一频道归到同一个节目下 |
| 小宇宙分享链接 | ⚠️ 尽力解析,失败时请手动填 RSS |
| Spotify | ❌ 拿不到 feed,请手动填 RSS |

解析出的 feed 会缓存,同一节目后续导入不再重新解析。

## 为什么广告段的文本和声音对不上(无法根治)

播客平台会**动态插入广告**:同一集在不同时间、不同网络下载,广告内容会被替换。
所以**转录时的那份音频,和你现在手机里听到的那份,广告可能不是同一批** ——
这一段的文本和声音注定对不上,重新转录也救不回来。

实测那一集:音频 167.4~197.4 秒(2:47~3:17)是一段广告,而且 Whisper 现在把这段
判为"无语音"直接跳过了。原本的第一版转录里那段是有文字的,说明广告确实被换过。

处理方式:**把这类"长时间跨度 + 极少文字"的空壳句去掉**(Whisper 会把一段广告压成
一条 `[167.4-197.4] "Thank you."` 这样的 30 秒句子)。去掉之后,那 30 秒里高亮会停在
上一条真实句子上,等真实内容回来再接上 —— 比卡在一条假句子上连贯得多。

## 关于时间轴漂移

**Whisper 在长音频上的时间戳会漂移。** 实测某一集在 3 分钟附近,转录记的时间比音频里的
真实时间**早了/晚了约 4 秒** —— 表现就是"高亮停在某句上不动,过一段又自己接上了"。

原因:Whisper 按 30 秒窗口推进,窗口边界会累积误差。在 58 分钟的文件上,这种漂移会出现在
若干区间。

**修法:分块转录。** 音频每 4 分钟切一块(块间重叠 12 秒),每块独立转录后把时间戳加回块偏移。
块内不累积误差,整集精度就稳住了。实测同一段音频:

| 内容 | 旧转录 | 分块转录 |
|---|---|---|
| "…actually needs. And the results are already there…" | 197.4s(偏) | **198.4s** |
| "…Own your agentic future today…" | 207.5s(偏) | **209.4s** |
| "AI spend is growing fast…" | 214.2s ✓ | 214.2s ✓ |

接缝用**时间戳**裁切(不做文本匹配):同一段音频在不同上下文里 Whisper 的断句会略有不同,
靠文本找重叠是概率性的,会重复或错位;时间戳是确定的。

**老转录可以校准**:

```bash
uv run et retranscribe <episode_id>     # 重转录并重建段落、逐句中译
```

## 关于"音频尾部有未转录内容"

播客平台会在音频里**动态插入广告**。实测 Hard Fork 那一集:音频 58:15,但转录只到 **52:31**,
尾部近 6 分钟是注入的广告,没有对应文本。

处理方式:**播到转录末尾后继续把音频放完**,只在源文件真正结束时才停下并提示"已到结尾"。
(曾经的 bug:转录一结束就宣布"已到结尾"并停住;此时再按播放,播放头会被拉回最后一句的起点,
听起来像"跳回前面重放"。)

## 已知限制

- **只处理你导入的那一集**,不做订阅轮询、不批量转历史(刻意的设计选择,见 DESIGN.md D7)。
- **句级播放,不是词级**。点一句话从这句开头播,**不勾连播时播完这句就停下**(回到该句起点,等你查词)。
- **转录只覆盖音频的一部分**时属正常现象(见上一节),不影响收听。
- **转录速度约 4~6 倍实时**(M5 实测):44 分钟整集约 7.7 分钟(≈5.7 倍);早期 3 分钟切片
  180 秒音频用 43 秒(≈4.2 倍,见 DESIGN.md D6)。1 小时约 10~15 分钟。
- **跟随滚动默认开**:点开始阅读就自动跟着播到的句子走。
  **你一旦自己滑屏超过约 110px,它自动关闭**,不再和你抢屏幕(状态栏会提示"已停止跟随")。
  勾上「连播」时会自动重新打开跟随。(DESIGN.md D16 原定"默认关",已按此修订。)
- **「◎ 定位」按钮**:点一下瞬间回到你正在读的那一句,并重新开始跟随。
  它定位的是"你读到哪"(视野上三分之一处那句),而不是永远跳回正在播的那句 ——
  所以你滑到后面看完一段,一键就能回到刚才的位置。跟随中按钮是实心的。
- **播放位置会被记住**,重新打开那一集时提示"上次听到 mm:ss"。
- **可加到 iPhone 主屏**(PWA):Safari 分享 →「添加到主屏幕」,打开后是全屏无地址栏的。
- 中文播客不在目标场景内(已强制 `language=en`)。
