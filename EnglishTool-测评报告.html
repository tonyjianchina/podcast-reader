02 / 缺陷登记14 个被复现并修掉的问题

按严重度排序。每条都写了「用户会看到什么」「为什么」「怎么修的」「怎么确认修好了」。 其中 1 个阻断级、8 个严重级。

D-01 阻断 鉴权 / 启动

设了 ET_TOKEN 之后整个应用打不开(页面外壳也是 401 JSON)

表现
按 README 建议在局域网/外网设置 ET_TOKEN 后,浏览器打开首页只看到 {"detail":"unauthorized"},连"把 token 填进去"的机会都没有。
根因
app.py 的中间件只放行 /health,前端也完全没有 token 的概念(全文件搜不到 token 一词)。
修复
外壳与静态资源(/、manifest、icon)放行;首页把 token 注入页面;前端 api() 统一带上 Authorization,并支持 ?token= 手输一次后存本地、把地址栏里的 token 抹掉;认证方案大小写不敏感。
验证
K1–K6(6 条鉴权用例,独立实例 + 真 token)全绿
涉及
englishtool/app.pyweb/index.html
D-02 严重 阅读器 / 音频

✕ 停止播放器之后,再点任何句子都放不出声(静默失败)

表现
点播放条的 ✕ 收起播放器,然后再点正文里的句子:高亮会动、状态栏显示"播放中",但一点声音都没有,也没有任何报错。
根因
stopAndClose() 只把 audio.src 清空、把 playing.loaded 置 false;而 loadEpisode() 判断"这一集已经加载过"时只看 playing.loaded 标记。第二次进入时 src 是空的,于是 set currentTime / play() 全部作用在一个空源上。
修复
① 停播时把 audio 元件整个放掉(而不是只清 src);② loadEpisode() 判定"已加载"时同时检查 src 还在不在;③ 清空 src / 换源过程中浏览器补发的 MEDIA_ERR_SRC_NOT_SUPPORTED 不再当作"音频加载失败"报给用户。
验证
E9 + 自动化过程中真实复现并回归
涉及
web/index.html
D-03 严重 阅读器 / 音频

audio 元件一旦离开文档,后续所有播放静默失效

表现
从列表进正文、点句子,页面看起来一切正常(底部播放条在报"播放中"),但元素其实不在 DOM 里,声音永远出不来。
根因
ensureAudio() 把 audio 缓存在脚本级变量里,只要它被移出过 DOM(页面被别的脚本动过、或浏览器回收了节点),就再也回不到文档里。
修复
ensureAudio() 用 isConnected 兜底:元件不在文档里就丢掉重建。
验证
J4(快速连点)+ 自动化清理流程下的回归
涉及
web/index.html
D-04 严重 设置持久化

字号设置不持久化,刷新就回到默认

表现
语速、连播、中译、播放位置都记得住,唯独字号每次打开都要重调。
根因
字号只写了 CSS 变量,既没写 localStorage,启动时也没有读回来。
修复
字号写进 localStorage(et.fs),启动时回填。
验证
F2(真刷新后字号仍是 24px)
涉及
web/index.html
D-05 严重 路由 / 列表

冷启动直接进某一集时,列表永远是空的

表现
从书签/分享链接打开 /#<单集>,读完点「← 列表」——列表显示"还没有内容。粘贴一个播客链接开始。",要手动刷新才出得来。
根因
启动逻辑是 if(hash) 进正文 else 拉列表;直接带 hash 进来时 loadList() 从来没被调用过。
修复
列表永远拉一次,与 hash 无关。
验证
A1/B1(冷启动带 hash 的路径)+ 真机回归
涉及
web/index.html
D-06 严重 鉴权 / 前端

没设 token 的部署里,前端会带一个假 token 去请求

表现
未开启鉴权的部署中,ET_TOKEN 变成字面量 '__ET_TOKEN__';此时从 URL 用 ?token=xxx 进来的 token 永远不会被保存下来(进不去也退不出)。
根因
占位符判断写反了(注入的占位符本身被当成"服务端已注入 token")。
修复
占位符一律视为"没有 token";真 token 才注入。
验证
K1–K6 + 真机冒烟(localStorage 里不再出现假 token)
涉及
web/index.html
D-07 严重 稳定性

worker 挂掉之后 /health 还在报 running:true,导入永远排队

表现
后台批处理一旦异常退出,界面上不做任何提示;导入的链接永远停在"排队",用户不知道发生了什么。
根因
running 是一个启动时置 True、之后再不更新的布尔量;create_task 的异常没有任何人读。
修复
worker 任务挂 done-callback:异常时打印并清 running;/health 的 running 由任务真实状态推导,另有 worker_healthy 字段。
验证
I8 + 代码审查(用不可打开的 DB 路径复现过死掉的 worker)
涉及
englishtool/app.pyenglishtool/pipeline.py
D-08 严重 存储

生词重复入库,而且返回的 id 是旧的,客户端永远删不掉自己刚建的那条

表现
同一句话里连着标记两次"生词",库里会出现两行;删掉返回的那个 id 之后,另一行还在,界面上看起来"删了没反应"。
根因
SQLite 的 UNIQUE 认为 NULL 互不相等;episode_id/seg_idx 为 NULL 时 INSERT OR IGNORE 完全不去重,随后的 SELECT ... AND seg_idx IS ? 又命中了最早那行。
修复
改成"按归一化键先查后插",返回真正插入的那一行 id;接口层对 seg_idx / episode_id 做类型校验。
验证
后端回归(连续两次 POST 只留一行、返回同一个 id)
涉及
englishtool/db.pyenglishtool/app.py
D-09 严重 可恢复性

中断的单集永远不会被重新处理,但日志说"续跑 1 个"

表现
进程在转录中途被杀,重启后那一集永远停在"转录中…",既不继续也不失败。
根因
续跑逻辑对非 pending 状态调用了只认 pending 的原子抢占,于是一个都没抢到,却仍然打印了"续跑 N 个"。
修复
续跑前先把中间态回退成 pending,再抢占;日志改成"实际续跑/总数"。
验证
代码审查 + 状态机回归
涉及
englishtool/pipeline.py
D-10 一般 前端错误处理

卡在中间态的单集没有重试入口,失败态也不显示原因

表现

根因
重试按钮的显示条件是 error 非空。
修复
只要不是 ready 就给出状态 + 原因 + 重试按钮;重试失败要显示失败原因。
验证
I6 + 失败态夹具

D-11 一般 中译

半截中译会被当成"已翻译完成",剩下的一半永远补不上

表现
翻译按批写入,一次批次失败就留下半集中译;再点中译开关,后端回答"已经翻过",于是文章一半有中文一半没有。
根因
has_translations() 只判断"有没有一行",而不是覆盖率。
修复
改为按覆盖率判断(≥95% 才算完成),补翻时已有句子不会重复花钱;接口返回已翻/总句数。

D-13 一般 健壮性

客户端传错 JSON 类型会变成 500,以及换源过程中的假"加载失败"

表现
{"url":123} / {"lemma":[]} 这类明显的客户端错误返回 500;清空音频源时状态栏会闪一句"音频加载失败"。

# 结果落在 .qa/out/run-<tag>.json

相(phase)的含义

  • main — 桌面视口,从冷启动到播放器、释义、中译、持久化。 需要「刷新」的用例会自己抛 RELOAD_MARKER,宿主据此整页重载后接着跑下半段(跨刷新的行为只能这么测)。
  • mobile — 390×844 视口,查横向溢出、工具栏重叠、全屏播放器是否都在屏内。
  • coldstart — 地址栏直接 /#<id> 整页加载。
  • offline — 把页面里的 fetch/XHR 全拒掉(页面外壳照常),验证离线缓存路径。
  • broken / failed — 音频文件丢失、处理失败这两条边角状态。
  • auth — 另起一个开了 ET_TOKEN 的实例,验证鉴权下的完整可用性。

05 / 这一轮没测到什么说清楚边界

  • 导入 → 转录 → 分段的真实长跑:解析真实播客链接、下载 56MB 音频、Whisper 转录 6~10 分钟。 本轮只验证了它们的失败路径(非法链接、网络不通、worker 挂掉)与状态机的可恢复性。 发出去之前建议你自己粘一个链接跑一集完整流程。
  • iOS / Safari 真机:PWA 的「添加到主屏幕」、底部安全区、iOS 的音频自动播放策略只在 Chromium 上验证过。 manifest 与 icon.svg 可访问性有用例覆盖,但真机全屏观感需要你自己看一眼。
  • 长时间播放的稳定性:用 60 秒短音频覆盖了逐句停、连播推进、进度条拖拽、位置记忆; 「连听一小时、切来切去、后台标签页」这种长跑没测。
  • 真机外放音质与断句观感:自动化只能验证播放头与高亮对齐、句边界是否按预期停下, 「听起来别扭不别扭」是人的判断。
  • 多设备/多标签同时使用:单一 token、无账号体系,并发写没有专门压测。
